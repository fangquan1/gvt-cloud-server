# 2026-06-22 current dynamic partial global guard

## 本轮目标

降低低带宽模式下播放视频、秒表、闪烁小区域时的画面拼接感，同时保持普通 `gvt_spice_viewer` 兼容：不发送 ROI 小图 H.265 给不具备 ROI compositor 的客户端，但在检测到连续/动态 partial 后 1-2 帧内切回 full-frame global。

## 参考实现观察

- Sunshine/PipeWire 路径使用 damage metadata 辅助判定帧是否有变化；视频编码时间线仍是连续整帧，damage 主要用于跳过冗余帧，见 `C:\job\opencode\sunshine\src\platform\linux\pipewire.cpp` 的 `SPA_META_VideoDamage` 和 redundant buffer 判断。
- Sunshine/Moonlight 对网络/参考帧恢复使用 IDR/RFI 机制，见 `C:\job\opencode\sunshine\src\stream.cpp` 的 `IDX_REQUEST_IDR_FRAME` / `IDX_INVALIDATE_REF_FRAMES` 处理；不是把独立小块 H.265 直接给普通播放器当全帧播。
- 因此本轮保持普通路径为 full-size H.265 帧：static 跳过，small partial 可降码率，但持续/动态 partial 要快速升 global。

## 改动摘要

- 修复动态 partial 升 global 的触发条件：
  - 旧逻辑：`dynamic_candidate = gdpy->low_bandwidth_roi && partial_candidate`
  - 新逻辑：`dynamic_candidate = gdpy->low_bandwidth && partial_candidate`
- 这样 `LOW_BANDWIDTH=1` 且 `ROI_PATCH_VIDEO=0` 时，普通 viewer 不会收到 ROI 小图，但动态/连续 partial 仍会触发全局帧保护。
- 同步更新 `patches/qemu-gvt-stream.patch` 和 `SERVER.md`。

## 结论

- 异常分辨率问题继续被保护：`ROI_PATCH_VIDEO=0` 时 `streamd_roi=0`，普通 viewer 不再收到小图 H.265。
- 动态 partial 升 global 已恢复：小区域变化在 1 帧 partial 后立即切到 full-frame global，且后续保持 global burst，符合 1-2 帧内动态适配目标。
- 静态场景仍能跳过大量帧：smoke 中 `dirty_skipped=1187`，保持低带宽收益。
